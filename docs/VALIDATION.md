# 실제 검증 결과

검증일: 2026-10-23 (Asia/Seoul). Windows, Node 26.7.0, Next.js 16.4.2, React 19.3.1, TypeScript 6.0.3, pdf-lib 1.17.1, PDF.js 6.4.299. 설치 버전과 package-lock.json을 고정했다.

## 실행 결과

| 검사 | 결과 |
|---|---|
| `npm run typecheck` | 통과, strict 활성 |
| `npm run lint` | 통과, 오류/경고 없음 |
| `npm test` | 2개 파일, 12개 테스트 통과 |
| `npm run build` | webpack 프로덕션 정적 내보내기 성공, out 생성 |
| `npm run test:e2e` | Chromium desktop / Pixel 7 에뮬레이션 각 4개, 총 8개 통과 |
| `npm audit --omit=dev --json` | 취약점 0개 |
| 전체 개발 의존성 audit | high 5개 남음: braces → micromatch → fast-glob → Next ESLint plugin/config 경로 |

개발 의존성 경고는 실행 사이트의 JS에 포함되지 않는다. 무조건적인 `audit fix --force`는 Next ESLint를 구버전으로 내리므로 실행하지 않았다. 공급자의 수정 버전 확인과 업데이트는 후속 작업이다. 0건 결과는 감사 실행 시 알려진 항목에 한정되며 보안 전체 보장을 의미하지 않는다.

## 실제 파일 검증

- 브라우저에서 600×800 PNG 생성 → 300×400 JPG로 변환 → 다운로드 파일의 JPEG 서명과 실제 크기를 검사. 대표 결과: 5,919바이트, 100,000바이트 제한 충족. 화면 이미지의 자연 크기도 300×400 확인.
- PNG/WebP 다운로드 파일의 실제 서명 검사.
- 1바이트 목표가 실패하면 오류를 표시하고 다운로드 링크가 없는지 확인.
- 가짜 JPG 오류, 공유 설정 URL 재접속 후 640px 복원 확인.
- 이미지 2장으로 PDF 생성, PDF 두 개를 4페이지로 합치고 4,1-2를 3페이지로 추출. 다운로드 PDF를 pdf-lib로 다시 읽어 페이지 수 확인.
- PDF.js 로컬 worker가 결과 첫 페이지를 실제 렌더링하는지 확인.
- 이미지와 PDF 처리 전체에서 외부 요청 및 GET/HEAD 외 쓰기 요청 0건 관찰. 보안 헤더가 적용된 로컬 정적 서버를 대상으로 검사.
- 바이트 경계 100000/100001, 비단조 인코더 응답, 페이지 순서/중복/오류, 손상·위장·초과 페이지 PDF, 암호화 표시 PDF 거부 검사.
- PNG/JPEG/WebP 헤더 크기 파싱과 과대 픽셀 입력의 디코딩 전 거부 검사.
- 모바일 가로 넘침 없음. 데스크톱/모바일 전체 화면 캡처를 시각적으로 확인.

## 실패에서 수정한 내용

PDF.js 최신 버전에서 제거된 옵션을 제거하고 타입 검증을 통과했다. React effect의 URL 복원 처리를 수정했다. Windows에서 Turbopack 프로세스 연결 실패가 권한 확장 후에도 재현되어 webpack을 사용했다. 샌드박스는 빌드 경로 작성과 로컬 소켓 접속 일부를 차단하여 승인된 환경에서 빌드/브라우저 검증을 실행했다.

초기 E2E는 CSP가 막는 Blob fetch로 결과를 읽어 실패했으므로 보안 정책을 약화하지 않고 실제 다운로드 파일을 검사하도록 수정했다. Next route announcer와 입력의 접근성 이름 때문에 발생한 테스트 선택자 오류도 수정했다. 최종 테스트는 실패 기록과 구분하여 재실행했다.

## 아직 검증하지 않은 사항

- Cloudflare/GitHub에 실제 배포 또는 CI 실행. 배포 가이드와 CI 파일만 제공.
- Safari/Firefox, 실물 iPhone/Android, 모든 기기의 메모리 상한과 다운로드 동작.
- 모든 실제 암호화 방식/EXIF 방향/극단적인 압축 PDF. 암호화 테스트는 라이브러리의 암호화 거부 경로 검사다.
- 실제 도메인의 검색 색인, Core Web Vitals, AdSense 심사 및 수익.

PDF 처리는 메인 스레드의 pdf-lib를 사용하므로 큰/복잡한 문서의 즉각적인 중단과 메모리 상한을 강제하지 못한다. 취소는 결과 발행을 무효화하고 내부 처리가 끝날 때까지 입력을 잠근다. 공개 대규모 운영 전 별도 변환 worker와 실기기 스트레스 검증을 권장한다.

현재 도메인/운영자/문의 주소가 미설정된 비공개 검증용 상태다. noindex/robots 차단 상태의 정적 배포 파일이 제공되며 출시 전 실제 값으로 재빌드해야 한다. PDF 내용/메타데이터는 개인정보 제거를 보장하지 않는다.
